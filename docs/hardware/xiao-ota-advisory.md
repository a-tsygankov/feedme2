# XIAO OTA: read-only automatic version advisory (stage 1)

This branch implements **firmware update discovery only**, not OTA installation. The XIAO's running firmware reports version `0.1.41` and, while paired and online, requests `GET /api/device/firmware/check` over the existing CA-validated HTTPS transport. The first check is on the next eligible network tick, and subsequent checks occur at most once per six hours while running. USB `fwcheck` forces an advisory refresh; `netstatus` prints current/latest version, availability and HTTP status. `installSupported` is **always false**. No image URL, binary download, flash writes, reboot or auto-install exists.

The API requires the **currently valid device Bearer token** and uses the database device's hardware model and firmware version, not caller-supplied identity. Only `xiao-esp32s3-sense-scale` is eligible. Releases are opt-in rows in `firmware_releases` (migration 0005), with `active = 0` by default. There is deliberately **no public publishing endpoint**; an operator must review and activate a row through an approved administrative migration/process. No releases are seeded, so fresh installations correctly report no update. The firmware accepts only valid `MAJOR.MINOR.PATCH` version strings and rejects inconsistent response flags and any server claim that installation is supported.

**Current limitation:** the backend uses the firmware version last reported at pairing, not an independent heartbeat from the scale. A scale flashed by USB while remaining paired can have a stale backend version. Before production OTA, add a version heartbeat with an authenticated device report and compare with the locally compiled firmware version. Until then, the firmware independently compares the advisory to its own build version and rejects mismatched flags.

**Remaining work for actual OTA:** cryptographically signed per-model release manifest with immutable image hash and size; trusted signing key on-device; bounded TLS download; verified dual-slot writing; first-boot health confirmation and rollback; downgrade protection; preservation of calibration/NVS/LittleFS queue; power-loss, safety and physical XIAO testing. The presence of dual app partitions alone is not OTA.

**Bench commands:** `fwcheck` (manual refresh), `netstatus` (advisory). Never use this firmware unattended with pets until the load path and physical overload stops have been validated.
